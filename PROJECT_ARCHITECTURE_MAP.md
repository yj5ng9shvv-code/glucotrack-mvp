## Main runtime flow

1. Public site loads static pages from `website_source`.
2. User opens `/app/`, loading Flutter web from `website_source/app` or a freshly built `build/web`.
3. Flutter app calls backend API under `/api` or configured `API_BASE_URL`.
4. Backend authenticates users/admins, reads/writes MySQL/MariaDB, and integrates Stripe/OpenAI/Google where configured.
5. Admin panel calls `/admin/*` routes for users, subscriptions, support, GDPR, help, about, referrals and audit.

## Dynamic use points checked

- Flutter named routes and `AppNavigator`.
- Platform MethodChannels: `glucotrack/voice`, `glucotrack/emergency`, `glucotrack/device`.
- Backend Express route registration in `server.js`, `admin.js`, `gdpr.js`, `help.js`, `about.js`, `referrals.js`.
- Static website scripts in `website_source`.
- SQL schema and installation scripts.
- Web app build artifact under `website_source/app`.
